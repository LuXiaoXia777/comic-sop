# 按叙事任务调用布局参考

读取项目 `资料/布局参考.json`；没有时读取本技能 [布局资料库](layout-library.json)。资料库来自用户整理的[参考漫画](https://my.feishu.cn/wiki/AXCgwZR94iXKfdkxyhpcw636nab)，来源顺序和原始点评可用于定位。离线或无飞书权限仍可使用本地提炼规则，不得声称已看过无法访问的原图。

## 每次创作都执行

1. 先确定本页开始和结束的变化：发现了什么、谁回应谁、关系或处境怎样改变。没有变化先改脚本，不靠复杂版式补救。
2. 选择一个主视觉，按叙事功能检索资料库。登场与行进考虑01、02；双方反应考虑03、06；连续动作考虑04、05；揭示环境考虑07、08；第三者发现考虑09；多方反应考虑10。这些是候选，不是必用模板。
3. 内部记录每页的参考编号、采用理由、阅读入口、主视觉、结束落点及连续性要求。可保存为期次JSON的 `layoutPlan`，不默认增加用户脚本表格列。无需逐页套满所有形式，也不把示例格数写死。
4. 原图可访问时，查看选中参考，借鉴构图功能；不能搬用原角色、年龄、服饰、对白、剧情或完成稿画风。参考中出现学生形象不代表新故事应采用学生角色。新故事人物与内容遵循用户已确认设定。
5. 将选择落实到整页出图描述：主次面积、景别、人物相对位置、视线、动作连接、留白、气泡和跨格边界。不要只写“高级排版”“参考某图”。即使不向用户展示提示词，这些约束也必须用于生成。
6. 看生成图片验收：遮住对白能否理解动作变化；缩略图有无清晰主视觉；逐个气泡阅读是否顺畅；跨格是否造成分身错觉；局部特写与整体的左右手、服饰、角度是否对应；重心、支撑、透视是否成立。版式不清先减干扰，再考虑增加格子。

## 持续维护

新增素材保留来源链接、定位顺序及用户原话，将观察、建议和待确认解释分开。用户说“舒服”不等于所有场景都应套这个布局；先分析主次、间距与节奏如何服务当前剧情。反馈形成个人偏好后写项目规则，不将某位用户的题材或口味强制给所有用户。

项目的 `资料/布局参考.json` 可独立修改；初始化和构建不覆盖它。更新公共资料库时按id合并新增条目，已有用户自定义条目必须保留。飞书是来源，不是自动同步接口；只有重新读取后才更新已核验内容。

HTML创作资料显示布局名称、适用情节、应用与检查，并可展开原始点评和观察。原图通过来源链接查看。公共包目前分发提炼规则，不嵌入第三方漫画扫描图；不要将没有验证的授权写成开源。
